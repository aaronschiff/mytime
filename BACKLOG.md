# Backlog

## Data-loss risks (from 2026-06-30 failure-point audit)

Ranked by likelihood of costing real unbilled money. Worst-case concern: losing tracked time that hasn't been invoiced yet.

1. **✅ DONE (2026-06-30) — Backup integrity + off-site.** Audit found the nightly backup had been *failing every night since install*: the deployed systemd unit on bbbee had dropped the `MYTIME_DB_PATH`/`MYTIME_BACKUP_DIR` env vars, so `backup.py` used wrong defaults (`/opt/mytime/...` source missing, `/var/backups/mytime` permission-denied). Last good backup was 5 days stale (2026-06-25). Fixes shipped: `deploy/backup.py` rewritten to take a transactionally consistent snapshot via SQLite's online backup API (replacing `shutil.copy2`), verify it (`integrity_check` + schema query), and exit non-zero discarding any bad file; defaults corrected to the real bbbee paths; systemd unit restored with explicit env vars; off-site rsync-over-SSH push to a separate VPS (different building) added via `MYTIME_OFFSITE_DEST` + a dedicated SSH key and config alias on the server. Verified end-to-end through systemd: backup → verify → off-site push → `success`. Local backups land on `/data` (RAID1 mirror, separate disks from the NVMe live DB). Tests: `tests/test_backup.py` (7, TDD). NB: off-site is rsync-without-`--delete` so it accumulates history independently of local pruning. **Still open:** jazzy firewall hardening (80/443 from Cloudflare ranges only, 22 from known IPs) — optional, see notes in chat.
2. **✅ DONE (2026-06-30) — Project delete no longer destroys tracked time.** `guards.delete_project` now refuses to delete any project that has tracked time: invoiced time still raises `ProjectHasInvoicesError`, and uninvoiced time raises the new `ProjectHasTimeError` (was: silently `DELETE`d every entry). Deletion is only allowed for projects with zero time entries (e.g. mistaken creates). The router catches both and re-renders the projects list with a real error banner (previously the block showed no message at all — delete silently no-op'd); added `.error` CSS and corrected the misleading "and its time entries" confirm text on both delete buttons (projects list + client detail). Client deletion was already guarded equivalently (`can_delete_client` → `ClientHasTimeError`). Tests: updated `test_guards.py` (raise + entries survive; empty project still deletable) and added `test_projects_routes.py::test_delete_blocked_with_uninvoiced_time`. Guidance to users: archive, don't delete. NB: still no soft-delete/undo/audit-log for the single-entry delete paths (today + time list), which remain hard deletes guarded only by invoice-lock + JS confirm — acceptable blast radius (one entry) but noted.
3. **✅ DONE (2026-06-30) — busy_timeout + WAL.** `db.configure_engine()` registers a `connect` listener setting `PRAGMA busy_timeout=5000` (per-connection; reapplied on every connect) and `PRAGMA journal_mode=WAL`. Verified WAL activates and the online-backup API still yields a consistent, verified backup from a WAL DB. Two collateral fixes the WAL change forced: (a) deploy rsync `--exclude` widened from `mytime.db` to `mytime.db*` — with `--delete` it would otherwise have deleted the live `mytime.db-wal` sidecar mid-deploy, losing un-checkpointed transactions; (b) `.gitignore` now ignores `*.db-wal`/`*.db-shm`/`*.db-journal`. README documents the hardening. Tests: `tests/test_db_config.py` (2). **Deliberately NOT done:** `foreign_keys=ON` — SQLite has FK enforcement off today and turning it on would break delete paths that leave dangling refs (e.g. `delete_client` orphans project `client_id`). Tracked separately below.
4. **✅ DONE (2026-06-30) — Silent data-zeroing / swallowed errors.** (a) Today add path (`/today/add`, save mode) now rejects an unparseable duration with a 400 + error banner instead of saving a silent 0-second entry — matching the pattern `/time/new` and `/time/{id}/edit` already used. (b) Migrations refactored into `db._apply_migration`, which swallows only "duplicate column name" (the idempotent already-applied case) and re-raises everything else (missing table, locked/full disk, malformed SQL) so real failures surface loudly. (c) `set-time` was already guarded (`seconds is not None`) so it never writes invalid input; the "no edit history" aspect is a separate audit-log feature, deferred. Tests: `test_today_routes.py::test_add_with_invalid_duration_is_rejected`, two `test_db_config.py` migration tests. **Minor leftover:** `invoices.py:81` still does `parse_duration(...) or 0` in invoice-build — same anti-pattern, but it under-invoices rather than losing tracked time (the TimeEntry is preserved), so lower priority; fix when touching invoicing.
5. **✅ DONE (2026-07-01) — Timer elapsed no longer OS-timezone/DST dependent.** `clock.now()` now returns **naive UTC** (was OS-local), establishing the convention that all stored datetimes are naive UTC; `live_elapsed` math is therefore independent of OS timezone and immune to DST. This also fixed a latent bug: `since_iso` appended `Z` to an OS-local time, so the live browser timer mis-displayed by the UTC offset on any non-UTC host (correct on bbbee only because it's UTC; the dev Mac was wrong). `today()` still uses `MYTIME_TIMEZONE` for the local calendar date. Added a backward-step clamp in `live_elapsed` (`max(0, delta)`) so an NTP backward step can't report/bank less than already-accrued seconds. Tests: `test_clock.py` + 2 in `test_timers_service.py`. **Deliberately deferred (no heartbeat):** forward NTP steps are unhandled, but on bbbee (physical, always-on, UTC, disciplined clock that slews not steps) steady-state forward steps are sub-second; a >15min forward step needs an abnormal event (dead RTC + reboot mid-timer), backstopped by the 4h "still running" notification and editable elapsed. Residual only.
6. **🟡 FK enforcement off (deferred from #3).** SQLite runs with `foreign_keys=OFF`, so orphaned references are possible — e.g. `delete_client` removes a client while projects still hold its `client_id`. Enabling `PRAGMA foreign_keys=ON` needs an audit of every delete path plus a one-off cleanup of any existing orphans, with tests, before flipping it on. Not a direct time-loss risk, but a data-integrity gap.

## Deferred features for future work

- **Midnight rollover:** A timer left running overnight already appears in today's view (the `running_since IS NOT NULL` clause) and can be stopped normally. The entry retains its original date, which is correct. What's unresolved is *auto-stopping* at midnight if desired.
- **Auth & HTTPS:** If app is ever exposed beyond trusted LAN, add authentication (basic auth or OIDC) and enforce HTTPS.
- **CSV export:** Export time entries or invoice history to CSV for accounting/reconciliation.
- **Time-entry templates:** Save and reuse common time-entry descriptions.
- **Bulk invoice operations:** Void or re-lock multiple invoices at once.
- **Dark mode:** UI theme toggle.
