# Backlog

## Deferred features for future work

- **Inline elapsed editor (web Today page) submits its rounded prefill on blur.** Found during the 2026-07-28 timer-undercount audit but left out of scope: clicking a stopped entry's elapsed time opens the inline editor prefilled with the minute-rounded HH:MM (`_today_body.html`), and `today.html`'s blur handler submits on any click-away — so an accidental open + click elsewhere rewrites the exact stored seconds with the rounded value (±30s, unbiased). Fix ideas: skip the set-time POST when the value equals the prefill (mirror the `duration_prefill` pattern the edit forms now use), or close without submitting on blur (Enter-only submit). The menubar's inline editor submits only on Enter, so it's unaffected.

- **Auth & HTTPS — resolved via Tailscale (2026-07-10):** Tailscale was adopted for this LAN (see README's "Remote access" note). `tailscale serve` now exposes mytime over a real, auto-renewing HTTPS cert on a tailnet-only address, resolving the "Not Secure" warning and enabling secure remote access. Security boundary is Tailscale tailnet membership (confirmed single-user tailnet — only the user's own devices), not application-level auth; app-level auth was deliberately not added given that trust boundary. LAN access (`http://bbbee.local:8000`) is unchanged and still available. Revisit app-level auth only if the tailnet is ever shared with other people. See `docs/superpowers/specs/2026-07-10-tailscale-remote-access-design.md`.
