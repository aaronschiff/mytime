  - **Check web app for the same edit-a-running-entry data-loss bug.** Final review of the menubar app (2026-07-05) found that editing a running entry without touching the duration field silently discarded its accumulated running time, because the edit form prefilled duration from stale stored `base_seconds` rather than live elapsed, and `edit_entry` overwrites the total unconditionally from the submitted duration. Fixed on the menubar client by prefilling from live elapsed instead. The web app's own Time-page edit form (`mytime/templates/*`) may have the same prefill issue against the same backend behavior — not checked yet.
